# Apophis 6.0.0

The no-module baseline is still pinned at 466,343 packets. Everything new that changes traffic or writes files is opt-in, so a default build is as it was.

## Opt-in capture options

- **VLAN tagging.** `--vlan` puts an 802.1Q tag on every frame. The ID follows the segment where the capture sees the flow (10.10.20.0/24 becomes 20), or one fixed ID with `--vlan 120`. `--vlan-qinq` adds an outer 802.1ad tag. The tag goes on before padding, so a tagged frame is not always exactly 4 bytes longer. Byte counts in the manifest are bytes as written. The option is part of the build parameters, so a tagged and an untagged build never share a held capture. Off by default.
- **Build exports.** `--exports` writes extra files beside the pcap: `truth` (one line per flow, tagged with its scenario), `ssl` (Zeek-style ssl.log and x509.log), `http` (Zeek-style http.log) and `pcapng` (the pcap converted, with optional per-packet scenario comments and an optional embedded TLS key log). Any export also writes a small tag file. The logs are Zeek-style: Zeek's columns, filled by this app's own rules and not yet compared with a real Zeek run. The files are a fixed function of the pcap and its tag file. Two rebuilds are not byte-identical, because certificates and some payload bytes are random. Flow idle times for UDP and ICMP are placeholders. Off by default.
- **Dual-stack IPv6.** `--ipv6 [share]` adds a slice of IPv6 traffic after the day: neighbour discovery, router advertisements, multicast listener messages, DHCPv6, and DNS, HTTPS and SMB flows from a share of the workstations (25% by default). Addresses are derived from the company identity (private ULAs inside, 2001:db8::/32 outside). The slice carries its own `v6:` tags and uses private random streams, so removing those frames leaves the option-off capture. The Zeek-style logs and the flow files read IPv4 only. Checked with independent IPv6 checks and, where available, Wireshark's command-line dissector, not against a real network or a sensor. Command line and API only. Off by default.
- **IPv6 scenario variants.** A campaign option `ip_family` (`v4` default, `v6`, `dual`) runs actions over IPv6, and two scenarios are new: an IPv6 rogue router advertisement with DHCPv6 takeover (mitm6 style, with an SMB relay leg over IPv4) and an IPv6 neighbour-discovery flood. Both are ordinary scenario entries. What a sensor raises is expected, not observed.
- **Flow export.** `--exports ipfix` and `--exports netflow9` write `<name>-ipfix.pcap` or `-netflow9.pcap`, UDP datagrams from a synthetic exporter to a synthetic collector in the documentation range, plus a CSV of the same records. One record per direction, no active-timeout splitting, and interfaces, addresses and the scenario-tag element are synthetic. The flow table reads untagged IPv4 only, so VLAN-tagged and IPv6 frames produce no records. Decoded in the tests with Wireshark's command-line dissector and an independent decoder; acceptance by a real collector is not verified.
- **Tunnel carriers.** `--tunnel CARRIER:SCENARIO[,SCENARIO]` wraps a scenario's frames in GRE, VXLAN or 6in4 (`*` for every scenario, `normal-day` for the baseline), or `network_options.tunnels` in the API. The outer packet never sets Don't Fragment and is split at the rule's `mtu` (1500 by default), so a wrapped build has more frames. The wrapper draws no random numbers, so the inner frames equal the untunneled build. The manifest records `network.tunnels`, and the checkers take `--decap gre,vxlan,6in4`. Known limit: with VLAN tagging also on, a tunneled frame between two hosts on the same subnet gets the default VLAN ID. The flow files read untagged IPv4 TCP, UDP and ICMP, so inner frames are not in them. Not replayed at a standard MTU and not run against a sensor. Command line and API only. Off by default.
- **Controls in Compose.** VLAN tagging and the four earlier exports now have controls in Compose, under Network options and Exports, driven by one options table. Each export shows a rough size. IPv6 and flow export are not in the table yet.
- **Manifest additions.** The manifest records each scenario's first and last packet number and its active time spans, and the VLAN and export settings. A flow-table and log writer library for Zeek-style conn.log and dns.log exists, but is not a build option yet.

## Slicing and replay

- **The pcap slicer.** `tools/slice_pcap.py` copies one scenario out of a finished build into a smaller pcap, with a sidecar that cites the source hash and the original packet numbers. Kind A is the scenario's time window and is the faithful one. Kinds B and C keep fewer or no baseline packets and are experiments. Timestamps are not changed; replay at 1x, and note that moving dates by days makes certificate and ticket times in the payloads disagree with packet times. The slicer is a source-tree tool and is not in the packaged app.
- **The replay record.** Each replay writes `<name>.replay-<id>.json` beside the capture: the file and its hash, speed, range, times, packets sent, how it ended, the kind of interface (never its name), your label and note. It never holds a sensor address, key, token or error text. Replay is still done by a person in the app and has no agent verb.
- **Resume.** A stopped or failed single-pass replay can resume from the next unsent packet, starting a few packets earlier (500 by default) so nothing is lost at the join. A resumed run is recorded as not a continuous 1x run. The Replay page now lists a capture's records, shows each one, and offers Resume from packet N, which fills the form and leaves Start replay as the one way in.
- **The slice picker.** Captures has Cut a slice of one scenario: choose a capture, scenario, kind and padding, see a preview, and cut. The slicer file is not in the packaged apps, so there the picker reports that it is not part of the build.

## Linux

- **Keys.** The key store picks a backend at start: the macOS Keychain, the Linux desktop keyring through `secret-tool` when one answers, or a private 0600 file. `secret-tool` is found in system folders only. An agent token kept in the older token file is no longer read; create a new one. The keyring path is tested with simulated answers, not a live keyring.
- **The app.** A Linux tarball (`apophis-<version>-linux-<arch>.tar.gz`, x86_64 and aarch64, with `SHA256SUMS`) holds the app and its own Python, built in containers on AlmaLinux 9 (glibc 2.34). It was checked by building the pinned baseline inside the bundle on Ubuntu 22.04 and AlmaLinux 9 for x86_64. Whether an aarch64 bundle has been run is not confirmed. The updater and the slice picker are not confirmed to work in it.
- **Packages.** Both architectures also come as a `.deb`, an `.rpm` and an AppImage, with one `SHA256SUMS` over every file. The deb and rpm install under `/usr/lib/apophis` with root-owned files and recommend `tcpreplay`. `Dockerfile.app` builds an Ubuntu 22.04 image from the deb. The server listens on 127.0.0.1 only, so the interface works only with `docker run --network host`, and replay does not work in the container. The packages are unsigned. Not verified: the x86_64 AppImage runtime starting under emulation (its contents were unpacked instead), a real RHEL 9 (AlmaLinux 9 stood in), and Docker on a real x86_64 host.
- **Updates.** A tarball or AppImage copy can replace itself with a newer full release. The app checks a signed per-architecture manifest, then the download's sha256, then for a tarball the sha256 of every file against the signed list, and changes nothing if a step fails. The old copy is kept in `app-previous`. A deb or rpm copy is refused with a message to use the package manager, and the app never asks for a password. Maintainers can run `packaging/linux/og-proof-linux` on a Linux machine. Its limits: it drives the updater from the source tree against a frozen 5.5 bundle, its new bundle is the old one re-versioned, and the AppImage is swapped but not started.
- **Release path.** One script, `packaging/linux/release-linux.sh`, builds and collects the eight assets (tarball, deb, rpm and AppImage for each architecture) and writes one `SHA256SUMS` over all of them. Users check it with `sha256sum -c --ignore-missing SHA256SUMS`. The owner signs the updater manifests as a separate step, and the assets are attached to a draft release only.
- **Replay.** Replay now has the pieces for Linux: install commands for the distribution's package manager, an interface list that puts loopback, virtual interfaces and the default-route interface last with a warning, and an elevation order of root, the `cap_net_raw` capability, passwordless `sudo` for that `tcpreplay`, then `pkexec`. The fix when none applies is `sudo setcap cap_net_raw+ep` on `tcpreplay`. This was tested with simulated system answers and has not yet been confirmed on a Linux machine. 

## Speed

- A default build is about 40% faster (9.1 s to 5.3 s in the test): RSA keys are generated ahead on spare cores. Output and the 466,343-packet pin are unchanged.
- The campaign estimate is faster and cached. The truth, IPFIX and NetFlow exports share one pass over the flows, and the outputs are byte-identical to before.
- The replay checks (10 s) and the update check (60 s) are cached, so a repeat within that time shows the earlier result.
- A missing inventory file is now recreated at the path a build asks for, never inside the source tree.

## Scenario expectations

`scenario_expectations.json` describes all 81 scenarios in data: what the traffic does, the roles, the ATT&CK techniques, and the detection classes a passive sensor could plausibly raise, each with a strength and a status that starts at authored. `tools/check_expectations.py` validates the file, and a test fails when a scenario has no entry. Nothing in the app scores a sensor against it, and there is no screen for it yet.

## Code quality

- **A lint gate.** `tools/lint_rules.py` is a standard-library linter with 22 rules and a baseline that only shrinks. It runs locally and in CI. `docs/code-standards.md` states the rules and the no-hack policy.
- **For contributors.** `README-GUI.md` ends with a short contributor note.

## Security hardening

- **Replay run state is per user.** The stop file, logs and run record live in a private `run` folder inside the settings folder, not in a shared temp folder. The app checks that the paths in a run record are its own before it uses them. Run folders older than 14 days are removed.
- **Root runs only a root-owned `tcpreplay`.** A copy in a folder you own is refused with a one-time command that installs a root-owned copy in `/usr/local/bin`. On macOS every library it loads must also sit in a root-owned, non-writable folder. Homebrew's `tcpreplay` loads `libdnet` from a folder you own, so it is refused even as a root-owned copy, and the message names the library. Use MacPorts (`sudo port install tcpreplay`), a statically linked build, or run the app as root. Replay without administrator rights is unaffected. On macOS the administrator shell now writes its log into a root-owned folder it creates itself.
- **Agent API limits.** `capture/list` ignores `out_dir` and lists the app's own folder. The `scale` of a campaign run or estimate is capped at the limit the page uses.
- **Earlier builds.** A rebuild holds only the capture's own files (names that start with its name) and the company's threat-collection files. A file written with a custom `--iocs-prefix` is overwritten, not held.
- **Linux updates.** An install is classed by where the running program lives, so an AppImage-launched deb or tarball is not mistaken for an AppImage. A tarball swap needs the app and launcher layout. A signed release is checked by its signature, not by a file existing.
- **Server pages forbid script.** `/diagram`, `/profile`, `/report` and `/about` are sent with a header, and a meta tag in the page, that forbid script.
- **The launch code.** The address the app prints ends in a one-time `?launch=` code. This is built for one person on their own machine: on a shared computer the code is visible in the process list while the app starts, a local program that loads it first takes the session (restart the app), and a browser restart loses the session cookie, so reopen the printed address.
- **Pasted lists.** A STIX paste with very long patterns is read in linear time, and non-ASCII digits in a pasted CIDR no longer abort a build.
- **Helpers come from system folders.** `sudo`, `pkexec`, `getcap` and `secret-tool` are looked up in fixed system folders, never through PATH.
- **The audit log holds names only.** `agent-audit.log` records the time, verb, status and argument names, never a value. The settings folder is 0700 and the log 0600.
- **The agent token is cached for five seconds in memory,** so one request does not start one helper process. A change made through the key routes takes effect within that time.
